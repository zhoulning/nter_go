# 录音面试复盘 — 功能规划

- 版本：v1.0（规划稿，待确认后实现）
- 日期：2026-09-05
- 已确认决策：全链路一步到位（上传→转写→报告）；转写双通道（本地 faster-whisper 默认 + 云端 ASR 可切）；说话人区分用 LLM 语义推断（不做声纹分离）

---

## 1. 功能目标

面试结束后上传录音，系统自动转写文字稿，结合**目标岗位的 JD、关联的简历、以及你在面试中的实际回答**，生成一份结构化的**面试复盘报告**：

- 我被问了哪些问题（自动切题）
- 每个问题我答得怎么样（逐题点评：结构 / 深度 / 表达 + 参考要点 + 更好的回答示范）
- 对照 JD：哪些要求我展示出来了，哪些没覆盖到
- 面试官在关注什么（从提问分布推断团队技术栈与考察侧重）
- 整体评价 + 下一步行动清单
- 真实被问到的题**一键存入题库**，反哺后续的题目预测

一句话：让每一场面试都变成可度量的练兵，而不是面完就忘。

## 2. 用户体验流程

```
上传录音（关联 机会 + 轮次）
   →  后台转写（本地 whisper 或云端 ASR，进度可见）
   →  文字稿确认/微调（可编辑，带 [MM:SS] 时间戳）
   →  一键生成复盘报告（选择用哪份简历；后台生成，进度可见）
   →  报告页查看（逐题点评 / JD 对照 / 行动清单）
   →  真实题目一键存入题库；报告可导出 Markdown
```

## 3. 数据模型

```python
class Recording(SQLModel, table=True):
    id: int PK
    opportunity_id: int FK            # 所属机会
    round_id: int | None FK           # 关联轮次（可选，推荐关联）
    filename: str                     # 原始文件名
    filepath: str                     # data/uploads/recordings/ 内路径
    size: int                         # 字节数
    duration_sec: float | None        # ffprobe 读取
    transcript: str | None            # 文字稿（带 [MM:SS] 时间戳）
    transcript_engine: str | None     # whisper-small / glm-asr / manual
    status: str                       # uploaded / transcribing / transcribed / failed
    progress: int = 0                 # 转写进度 0-100
    error: str | None
    created_at

class ReviewReport(SQLModel, table=True):
    id: int PK
    recording_id: int FK unique       # 重新生成即覆盖
    model: str                        # 生成用的模型
    resume_id: int | None             # 生成时使用的简历
    report: str                       # 结构化报告（JSON 序列化）
    overall_score: int                # 总评 0-100
    question_count: int
    created_at
```

`Opportunity` 增加 `resume_id`（关联简历）：编辑弹窗里可选「用哪版简历投的这家」，复盘生成时默认使用；无关联时在生成对话框中临时选择。迁移仅需加一列。

## 4. API 设计

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/recordings` | multipart 上传（opportunity_id / round_id），存文件 + 读时长 |
| GET | `/api/recordings` | 列表（带机会/轮次信息、转写与复盘状态） |
| GET | `/api/recordings/{id}` | 详情（含文字稿、进度，供轮询） |
| DELETE | `/api/recordings/{id}` | 删除（连文件） |
| POST | `/api/recordings/{id}/transcribe` | 启动后台转写（body 指定 local / cloud） |
| PUT | `/api/recordings/{id}/transcript` | 手动粘贴 / 编辑保存文字稿 |
| POST | `/api/recordings/{id}/review` | 生成复盘报告（body: resume_id 可选），后台任务 |
| GET | `/api/reviews/{recording_id}` | 获取报告 |

后台任务用进程内线程池 + 内存任务表（与现有轻量风格一致），前端轮询状态接口。

## 5. 转写管道（双通道）

### 5.1 本地通道（默认）：faster-whisper

- 依赖：`faster-whisper`（pip，含 ctranslate2）；ffmpeg 已就绪
- 模型：默认 `small`，设置中可切 tiny/base/medium；首次使用自动下载（约 500MB），页面给出进度与引导
- 流程：上传文件 → ffmpeg 归一为 16k 单声道 wav → faster-whisper 逐段转写（VAD 过滤静音）→ 段落拼接为 `[MM:SS] 文本` 格式；进度按已处理时长 / 总时长写库
- 性能预期：CPU 下 1 小时录音约 10-20 分钟（small）；报告中如实标注

### 5.2 云端通道（可切换）：OpenAI audio 协议兼容

- 设置页新增「语音转写」区块：开关（本地/云端）+ 云端 base_url + api_key + 模型名（如硅基流动 SenseVoice、智谱 ASR 等，凡兼容 `/v1/audio/transcriptions` 协议均可）
- 大文件（>24MB）先用 ffmpeg 按 20 分钟切片，逐段上传转写后按时间戳拼接
- 适合长录音快速出稿；按量计费由服务商收取

### 5.3 手动通道（兜底）

- 上传的录音可直接手动粘贴文字稿（PUT transcript），标注 engine=manual，直接进入复盘环节——转写不可用时整条链路依然完整

## 6. AI 复盘管道

输入四件套：**文字稿 + JD（opportunity.jd_text）+ 简历文本（resume_id → Resume.text）+ 机会元信息（岗位/轮次类型）**。

说话人区分：不做声纹分离。Prompt 要求模型按「提问句式 / 回答句式」的语言特征把文字稿切成问答对，面试的一问一答节奏对此非常友好。

### 长度策略

- 文字稿 ≤ 24K 字符：单次调用直出（现有 glm-5.3 上下文足够）
- 超长：按时间戳边界分块，**两阶段 map-reduce**——Stage A 各块提取问答对 → 合并去重 → Stage B 统一点评与汇总

### 结构化输出（JSON Schema 约束 + 解析重试，复用现有基建）

```jsonc
{
  "overall": { "score": 82, "summary": "整体表现…", "highlights": ["…"], "weaknesses": ["…"] },
  "questions": [
    {
      "question": "讲一下你项目里的库存超卖怎么解决的",
      "topic": "项目深挖",
      "my_answer": "我的回答要点摘述",
      "scores": { "structure": 4, "depth": 3, "clarity": 4 },
      "good": ["有量化结果", "方案对比清晰"],
      "bad": ["没有主动提边界条件"],
      "reference": "参考答题要点…",
      "improved": "更好的回答示范…"
    }
  ],
  "jd_match": { "demonstrated": ["…"], "gaps": ["…"] },
  "interviewer_focus": "面试官反复追问 MySQL 与分布式，判断团队重度使用…",
  "action_items": ["复习 Redis 持久化细节", "准备量化项目收益的话术"],
  "questions_for_bank": [ { "content": "…", "dimension": "MySQL", "difficulty": "medium" } ]
}
```

## 7. 页面与入口

1. **侧边栏新增「录音复盘」页**（复盘与决策分组）：全部录音列表（公司 / 轮次 / 时长 / 转写状态与进度 / 复盘状态），顶部上传按钮；行点击进入该录音的「文字稿 + 报告」详情
2. **报告展示页**（录音详情）：头部总评分数环 + 模型/时间；总体评价卡（亮点 / 短板）；**逐题复盘**可折叠卡片（题目、回答要点、三维评分条、亮点 / 问题、参考要点、改进示范）；**JD 对照区**（✓ 已展示 / ⚠️ 差距）；面试官关注点；行动清单；底部操作：重新生成 / 导出 Markdown / **题目一键存入题库**（复用现有 `POST /api/questions`）
3. **详情抽屉**的轮次时间线区块：每轮增加「录音 / 复盘」入口与状态徽标，点击跳转对应录音详情
4. 机会编辑弹窗增加「关联简历」下拉

## 8. 依赖与安装

| 项 | 说明 |
|---|---|
| faster-whisper | pip 安装；Windows 首次需 VC++ 运行库（绝大多数机器已有），失败时页面给出排障指引 |
| 模型下载 | 首次转写自动下载（约 500MB，缓存于用户目录），页面展示一次性引导 |
| ffmpeg | 已安装 ✓（转码 / 切片 / 时长） |
| 云端 ASR | 需自行开通（OpenAI audio 协议兼容的服务商均可），设置页配置 |
| LLM | 复用现有智谱配置，单次复盘成本约几毛钱 |

## 9. 实现顺序（每步可用）

| 阶段 | 内容 | 验收 |
|---|---|---|
| P1 | 数据层 + 录音上传管理页（上传 / 列表 / 删除 / 时长 / 关联轮次） | 能传、能管 |
| P2 | 文字稿手动粘贴与编辑 | 不依赖转写即可准备文字稿 |
| P3 | **AI 复盘报告生成 + 报告展示页 + Markdown 导出**（核心价值闭环，用粘贴文字稿即可验收） | 粘贴文字稿出完整报告 |
| P4 | 机会关联简历 + 报告生成引入 JD / 简历对照 | 报告含 JD 对照区 |
| P5 | 本地 faster-whisper 转写管道（后台任务 + 进度 + 安装引导） | 上传录音自动出文字稿 |
| P6 | 云端 ASR 通道 + 设置页转写区块 + 题库一键入库 | 双通道可切换，真题入库 |

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| faster-whisper 在部分 Windows 机器安装/运行失败 | 安装引导 + 明确报错；云端通道与手动粘贴兜底 |
| CPU 转写慢 | 进度可视化；small 模型起步；云端通道加速 |
| 长文字稿超模型上下文 | 时间戳分块 map-reduce 两阶段 |
| 切题 / 评分不准 | 文字稿可编辑后重新生成；Prompt 持续调优 |
| 报告 JSON 输出不稳定 | Schema 约束 + 解析重试 + 失败可重试按钮 |
